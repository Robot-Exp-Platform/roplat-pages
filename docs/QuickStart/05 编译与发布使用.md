# 编译与发布使用

本页说明 roplat 项目如何构建、生成多语言文件和做质量检查。

## Rust-only

```powershell
cargo check -p my_robot
cargo run -p my_robot
cargo test -p my_robot
```

Rust-only 项目不需要 `build.rs`，也不需要 `roplat_py`。

## 多语言构建

多语言项目通常有 `build.rs`：

```rust
fn main() {
    if std::env::var("ROPLAT_PHASE").as_deref() == Ok("EXTRACT") {
        return;
    }

    roplat_build::BuildOrchestrator::new()
        .build()
        .expect("roplat code generation failed");
}
```

`BuildOrchestrator` 做三件事：

1. 子进程 `cargo check` 进入 `ROPLAT_PHASE=EXTRACT`，过程宏写 manifest。
2. 读取 manifest，生成 C++ / Python 文件。
3. 如果配置了 `NativeBuildConfig`，编译 C++ FFI 和用户源。

## 生成文件策略

| 文件 | 是否可编辑 |
|---|---|
| `cpp/roplat_gen/*` | 不可编辑 |
| `py/roplat_gen/*` | 不可编辑 |
| `cpp/src/<node>.h` | 可编辑，缺失时生成 |
| `py/<node>.py` | 可编辑，缺失时生成 |
| `src/msg.rs` | 用户源码 |
| `src/puppet.rs` | 用户源码 |

如果生成文件不对，改 Rust 声明或 build 配置，不要手改 `roplat_gen`。

## C++ backend

默认 `cc` backend：

```powershell
cargo check -p my_robot
```

切换 CMake：

```powershell
$env:ROPLAT_NATIVE_BACKEND = "cmake"
cargo check -p my_robot
```

## 推荐质量门禁

```powershell
cargo fmt
cargo check -p my_robot
cargo test -p my_robot
```

修改 roplat 公共 API 或多 crate 行为时再跑：

```powershell
cargo check --workspace
cargo test --workspace
```

## 常见失败

| 问题 | 处理 |
|---|---|
| Python puppet 找不到 `roplat_py` | 在 `[dependencies]` 添加 `roplat_py` |
| 生成文件不存在 | 先跑 `cargo check` |
| C++ include 找不到 | 检查 `roplat_cpp` 依赖和 `roplat_cpp/include` 路径 |
| 纯 Rust crate 编译变慢 | 检查是否误加 `roplat_py` 或 Python puppet |
| build.rs 递归/卡住 | 确认 `ROPLAT_PHASE=EXTRACT` 时直接 return |
